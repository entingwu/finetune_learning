## Q1 LLM 发展历程；InstructGPT 三阶段训练

**发展历程（口述版）**

GPT 系列是现代大模型发展的主线，一直采用 Transformer Decoder-only 架构，主要变化在规模和训练范式：

| 模型 | 时间 | 参数量 | 关键贡献 |
|---|---|---|---|
| GPT-1 | 2018.06 | 1.17 亿 | 验证了 Decoder-only 架构和“预训练 + 微调”范式 |
| GPT-2 | 2019 | 15.42 亿 | 采用 Pre-LayerNorm，展现零样本泛化能力和规模效应 |
| GPT-3 | 2020.05 | 1750 亿 | 提出上下文学习：靠任务描述和少量示例完成任务，无需额外训练 |
| InstructGPT | 2022 初 | 1750 亿 | 结构不变，变革训练范式，引入指令对齐和人类反馈 |
| ChatGPT | 2022.11 | 未公开 | 沿用 RLHF，改用多轮对话格式的数据，支持连贯对话 |

InstructGPT 要解决的问题是：GPT-3 只学会了预测下一个词，也就是语言的统计规律，并没有学会理解和执行人类指令。

**InstructGPT 三阶段训练（基于预训练好的 GPT-3）**

1. **监督微调（SFT）**
   - **做法：** 由人工撰写高质量的“指令-回答”样本，在上面做微调，训练目标仍是预测下一个 Token。
   - **目标：** 让模型初步具备理解和执行自然语言指令的能力。
2. **奖励模型（RM）**
   - **做法：** 用 SFT 模型对同一指令生成多个候选回答，由人工按质量、相关性、礼貌性、有用性排序，再用排序结果训练奖励模型。
   - **目标：** 让奖励模型模仿人类偏好，能给任意回答打分，作为下一阶段的反馈评估器。
3. **强化学习（RLHF）**
   - **做法：** 按“选取指令 → SFT 模型生成回答 → 奖励模型打分 → PPO 更新参数”的流程循环，以最大化奖励评分为目标。
   - **目标：** 让输出更符合人类意图，更真实、有用、安全。

## Q2 LLM 基础架构

典型的 LLM 分为三部分：

- **输入层：** 把文本分词后映射为词向量（Token Embedding），再加入位置编码，为后续层提供初始的语义和位置信息。
- **Transformer Block 堆叠层：** 这是核心计算单元，通常堆叠几十到上百层。
  - **自注意力：** 处理当前 token 时参考序列其他位置，捕捉长距离依赖。
  - **前馈网络：** 做非线性变换，提高表达能力。
  - **残差连接与归一化：** 保证深层训练时梯度传播稳定。
- **输出层：** 用线性投影把隐向量映射到词表维度，再经 Softmax 得到下一个 token 的概率。现代模型通常让输入词向量和输出投影层共享权重，以减少参数并提升训练效果。

## Q3 正余弦位置编码

**背景：** 自注意力本身不含顺序信息，所以需要显式加入位置编码。

**做法：** 用固定的正余弦函数为每个位置生成唯一向量，再与词向量相加：

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

**优点**
- 无需训练，不引入可学习参数。
- 可外推到比训练时更长的序列。
- 隐含相对位置信息：同一频率 ω 的分量内积为 `cos(ω(m−n))`，只与位置差有关。

**缺陷：** 这个优势在实际注意力计算中难以发挥。把 q、k 代入打分公式，令 `A = W_Q·W_Kᵀ`，展开得到：

```
score(m,n) = e_m A e_nᵀ + e_m A PE_nᵀ + PE_m A e_nᵀ + PE_m A PE_nᵀ
```

- 只有最后一项直接与相对位置相关。
- 这一项还夹着会随训练变化的矩阵 A，原有的几何结构难以稳定保持。
- 模型必须额外学习来重建相对位置信息，这个过程并不可靠，会影响训练稳定性和泛化。

## Q4 可学习位置编码

**做法：** 为每个位置分配一个独立的可训练向量，和其他参数一起更新，让模型从数据中学习位置表示。BERT、GPT-1/2 都用过这种方式。

**优点：** 灵活性高，贴合训练语料分布；优化方式和词向量一致，实现简单。

**缺陷**
- **缺乏长度外推能力：** 超出训练最大长度的位置没有对应的嵌入。
- **参数量随序列长度线性增长：** 支持长上下文时开销迅速增大。

## Q5 旋转位置编码（RoPE）

**设计目标：** 让注意力得分直接体现相对位置差，即 `score(m,n) = func(q_m, k_n, m−n)`。

**原理**

1. RoPE 不再把位置编码加到词向量上，而是直接作用于 q 和 k 向量。
2. 把 q、k 按维度两两分组，每对视为一个二维子向量。
3. 位置 m 的第 i 对子向量旋转 `m·θ_i`，其中 `θ_i = 10000^(−2i/d)`。
4. 计算第 i 对子向量对注意力的贡献：

```
q'_{m,i} (k'_{n,i})ᵀ = q_{m,i} R(mθ_i) R(nθ_i)ᵀ k_{n,i}ᵀ
                     = q_{m,i} R((m−n)θ_i) k_{n,i}ᵀ
```

这里用到旋转矩阵的两个性质：`R(θ)ᵀ = R(−θ)` 和 `R(θ₁)R(θ₂) = R(θ₁+θ₂)`。化简后每对子向量的贡献只取决于 q、k 和 `m−n`，所有子向量求和后就实现了设计目标。

**特点**
- **显式编码相对位置：** 得分天然依赖 `m−n`。
- **零参数且训练稳定：** 结构固定，几何性质不会被训练破坏。
- **长度外推能力强：** 不依赖训练长度，因此已成为当前 LLM 普遍采用的方案。

## Q6 MHA 与 KV Cache

**MHA 机制：** 把输入分别映射为多组 Query、Key、Value，在多个注意力头上并行计算注意力分布，让模型从不同子空间捕捉序列关系，提升表达能力。

**KV Cache：** 这是推理阶段的优化。
- **为什么需要：** 模型逐 token 生成，每个新 token 都要和所有历史 token 做注意力计算。如果每步都重算历史的 K 和 V，会产生大量重复计算。
- **怎么做：** 把历史 token 的 K、V 缓存下来，新 token 只需计算自己的 Q、K、V，再与缓存做注意力匹配，并把新的 k、v 追加进缓存。

**数据量太大的问题**
- 缓存会随序列变长、层数增加而不断累积。
- MHA 中每个头都独立生成并存储一组 K/V，又把缓存规模进一步放大。
- 结果是存储占用和内存带宽压力都很大，这是 MHA 在大模型推理中的主要问题。

可以这样估算（这条公式是补充内容，讲义里没有）：缓存量 ∝ 层数 × 头数 × 序列长度 × 每头 K/V 维度 × 2。

## Q7 MQA 与 GQA

**MQA（Multi-Query Attention，Google 2019）**
- **做法：** 每个头保留自己的 Query，但所有头共享同一套 K 和 V。
- **效果：** 需要缓存和读取的 K/V 大幅减少，存储和内存带宽压力降低，推理速度大幅提升。
- **代价：** 表达能力略有削弱，精度略逊于 MHA，但损失很小。

**GQA（Group-Query Attention，Google）**
- **做法：** 把注意力头分成多个组，组内共享一套 K/V，不同组之间的 K/V 相互独立。
- **定位：** 是 MHA 和 MQA 的折中。
  - **相比 MHA：** 不用为每个头维护 K/V，缓存和带宽压力大幅降低。
  - **相比 MQA：** 不再只有唯一一套 K/V，头之间多样性更高，表达能力更强。
- **效果：** 在推理效率和表达能力之间取得更优平衡，被 LLaMA、Qwen 等主流模型采用。

**一句话对比：** K/V 的组数从多到少依次是 MHA（等于头数）、GQA（等于组数）、MQA（1 组）。组数越少，缓存越小、推理越快，表达能力也略有下降。
