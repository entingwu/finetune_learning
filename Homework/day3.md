## Q1 微调的整体流程（口述）

> 微调前先判断问题来源，按由轻到重的顺序选方案：先试模型能否直接完成任务，再试提示词和示例；仍不行，再根据情况选 RAG、监督微调或继续预训练。确定要微调后，依次做模型选择、数据准备、方法选择、模型训练和效果评测。

**前置判断：微调是否合适（1.2）**

| 方法 | 适合解决 |
|---|---|
| 提示词工程 | 任务描述不清；不改参数，成本低，优先尝试 |
| RAG | 缺实时知识、私有知识，或需要引用来源 |
| 监督微调 | 输出格式、任务流程、术语、表达方式不稳定 |
| 继续预训练 | 需要适应领域语言分布 |

**五个环节（1.3）**

| 环节 | 要做的事 |
|---|---|
| 模型选择 | 根据任务、语言、模型规模、训练资源和许可证选基础模型 |
| 数据准备 | 收集、清洗、统一格式、划分和检查示范数据 |
| 方法选择 | 根据资源和效果要求，选全参数微调或参数高效微调 |
| 模型训练 | 执行训练，记录损失、梯度、显存、Checkpoint 和实验配置 |
| 效果评测 | 比较微调前后的表现，分析目标任务效果和通用能力的变化 |

## Q2 模型选择方法论

> 先按模型类型、模型系列和参数规模筛出少量候选，再用相同样本和标准做基线评测，最后在效果达标的模型中，优先选资源成本低、工具链完善的。

**选型因素（2.2）**

- **模型类型：**
  - **Instruct Model：** 已学过指令和对话方式，微调主要是调整术语、格式和流程。问答、抽取、生成和结构化输出通常优先选它。
  - **Base Model：** 还要学习理解指令和回答方式，需要更多、覆盖更全的指令数据。只有需要自建指令能力，或 Instruct Model 的已有行为与任务明显冲突时才考虑。
- **模型系列：** 常见有 Qwen、DeepSeek、GLM、Kimi、Llama、Mistral、Gemma。榜单（OpenCompass、Artificial Analysis、LiveBench、Arena）只用于初筛，要看与任务相关的分项成绩，并确认版本、类型和规模。
- **参数规模：** 下表只用于确定候选范围，参数量不等于能力。

| 应用场景 | 参考规模 |
|---|---|
| 分类、抽取、改写、格式转换 | 1.5B～7B |
| 客服问答、文本总结、内容生成 | 7B～14B |
| 领域问答、多步骤任务、代码生成 | 14B～32B |
| 复杂推理、开放式任务 | 32B～70B 及以上 |

**选型步骤（2.3）**

1. **确定候选：** 根据任务要求和资源限制排除明显不合适的模型。
2. **基线评测：** 所有候选使用相同的样本、标准和任务要求，生成参数尽量用模型推荐配置。重点看四点：
   - 是否理解任务要求
   - 结果是否基本正确
   - 能否处理困难样本和边界样本
   - 输出格式和流程是否稳定
3. **确定最终模型：** 综合基线结果、训练成本和推理成本。

**判断标准：** 核心任务都完成不了，就换模型；基本能完成、只是格式或流程不稳定，就保留为微调候选。基线结果之后还要用来判断微调是否带来了实际改进。

## Q3 🌟🌟🌟 数据工程，数据构造的方式

> 监督微调靠输入—输出示范让模型学习任务，所以数据决定模型学什么。保证样本准确、一致、符合任务要求，通常比单纯增加数量更重要。数据有三种构造方式：线上数据回流、已有数据转换和种子数据扩写。

**三种构造方式（3.2）**

| 方式 | 怎么做 | 适用情况 |
|---|---|---|
| 线上数据回流 | 项目初期先用线上大模型处理真实请求，通过日志保存提示词、必要上下文和模型响应，积累后转成微调样本 | 已有线上请求 |
| 已有数据转换 | 用 EasyDataset 上传 Markdown、PDF、DOCX、TXT 并分块，由大模型从块中提取问题、生成答案，人工审核后导出 | 有企业内部文档 |
| 种子数据扩写 | 人工或业务专家写结构化种子，由强模型扩写成不同表达、不同场景的变体 | 需要扩大规模和多样性 |

**种子数据**的核心是明确任务、回答要点和约束条件，字段按业务场景定，例如：

```json
{
  "场景": "车机蓝牙无法连接",
  "用户目标": "完成手机与车机蓝牙配对",
  "必要事实": ["手机蓝牙已开启", "车机蓝牙已开启"],
  "客服要求": ["确认手机型号", "指导删除旧配对记录后重新连接"]
}
```

一个种子可以扩写成单轮或多轮对话。模型由此学到同一任务的不同表达方式，泛化能力也会提高。

**对话数据结构（3.3）**

```json
{"messages": [
  {"role": "system", "content": "你是一个信息抽取助手。"},
  {"role": "user", "content": "从下面文本中抽取人物和地点：李明周一到达杭州。"},
  {"role": "assistant", "content": "人物：李明；地点：杭州。"}
]}
```

- **system：** 模型的身份、任务和规则，可以省略。
- **user：** 指令、问题和完成任务所需的输入。
- **assistant：** 模型要学习的目标回答。
- **chat_template：** `messages` 只是逻辑结构，由模型对应的模板转换成最终输入。

**数据划分（6.2.3.2）**

| 文件 | 用途 |
|---|---|
| train | 更新模型参数 |
| validation | 训练中评估和选最佳模型 |
| test | 基线测试和微调后评估 |

## Q4 LoRA 的原理和配置参数

**原理（4.2.2）**

> 全参数微调要学习完整的增量矩阵 ΔW。LoRA 观察到 ΔW 往往具有低秩结构，于是把它近似分解成两个小矩阵 A 和 B 的乘积。训练时冻结原始权重 W₀，只更新 A 和 B。

$$W = W_0 + \Delta W, \qquad \Delta W \approx AB, \qquad A \in \mathbb{R}^{d \times r},\ B \in \mathbb{R}^{r \times k},\ r \ll \min(d, k)$$

- **训练：** $y = xW_0 + xAB$，只有 A、B 更新。
- **推理有两种方式：**
  - **保留分支：** 继续用 $y = xW_0 + xAB$。
  - **合并权重：** 令 $W = W_0 + AB$，变回普通线性层 $y = xW$。
- **参数量：** 全参数需要 $dk$ 个，LoRA 只需要 $r(d+k)$ 个。

**代入 Qwen3-0.6B 的 `up_proj`（1024→3072，r=16）：**

| | 计算 | 参数量 |
|---|---|---|
| 全参数 | 1024 × 3072 | 3,145,728 |
| LoRA | 16 × (1024 + 3072) | 65,536（约 2.08%） |

整个模型实测可训练参数占 1.325%（10,092,544 / 761,724,928，`06_lora.ipynb` 的 `print_trainable_parameters()` 输出）。本地权重里 `lm_head` 和 `embed_tokens` 都存在，加载时没有绑定，所以 `lm_head` 被单独计入了总数。

**配置参数（4.2.3）**

| 参数 | 含义 | 怎么设 |
|---|---|---|
| `r` | 秩，决定 A、B 的大小；越大表达能力通常越强，参数也越多 | 常用 4、8、16、32、64，一般从 8 或 16 开始；任务复杂时适当增大 |
| `lora_alpha` | 决定缩放系数 $\alpha/r$，$\Delta W = \frac{\alpha}{r}AB$；$1/r$ 做归一化，$\alpha$ 调节整体强度 | 常见 r=8/α=16、r=16/α=32 |
| `target_modules` | 把 LoRA 插到哪些线性层；越多，可调权重和参数都越多 | Qwen 常用 `q/k/v/o_proj` 和 `gate/up/down_proj`；不同模型命名不同，要看实际结构 |
| `lora_dropout` | A、B 之前的 Dropout 概率，缓解过拟合 | 常用 0、0.05、0.1，一般从 0.05 开始；数据多可设 0，数据少或过拟合可增大到 0.1 |

**讲义的一处笔误：** 4.2.3.3 写 `gate_proj, up_proj, down_proj` 分别对应“升维、降维和门控”，顺序不对。按 [01_Qwen3.py:171-174](../01_Qwen3.py#L171-L174)，实际分别是门控、升维、降维。

## Q5 QLoRA 的原理，NF4，其他两个技术点

**原理（4.3.1）**

> LoRA 减少了梯度和优化器状态，但冻结的基础模型仍要放进显存，模型越大，这部分负担越重。QLoRA 把基础模型权重以 4-bit 存储并冻结，LoRA 参数以较高精度训练，同时保留可训练参数少和权重显存低两个优点。

**注意：** 主要量化的是线性层。Embedding、LayerNorm 和部分输出层继续使用较高精度（6.4.2.2）。

**量化的基本过程（4.3.2）**

1. 取一组权重的最大绝对值作为缩放因子 $s$，再把每个权重除以 $s$，归一化到 [-1, 1]。
2. 映射到最近的量化点，保存它的 4-bit 编码。
3. 计算时根据编码找到量化点，再乘以 $s$ 恢复近似值。这一步叫反量化，与原值的差异叫量化误差。

| 步骤 | 结果 |
|---|---|
| 原始权重 | 0.27, 0.58, -0.75, 1.52（absmax = 1.52） |
| 归一化 | 0.18, 0.38, -0.49, 1.00 |
| 最近量化点 | 0.2, 0.33, -0.47, 1.0 |
| 4-bit 编码 | 9, 10, 4, 15 |
| 反量化 | 0.304, 0.5016, -0.7144, 1.52 |

实际会把权重切成多个块，每块单独算缩放因子（分块量化），避免少量极端值扩大整体的量化范围。块越小，误差通常越好控制，但缩放因子也越多。

**三个技术点（4.3.3）**

| 技术 | 解决什么问题 | 怎么做 |
|---|---|---|
| **NF4 量化** | 权重近似零中心正态分布，均匀量化在零附近表示能力不足 | 把标准正态分布按累积概率分成 16 个等概率区间，取每个区间的中位数作为量化点，使量化点在 0 附近更密、两端更疏 |
| **双重量化** | 分块产生大量缩放因子，以 FP32 保存占显存 | 把缩放因子每 256 个分为一组，用 8-bit 做二次量化 |
| **分页优化器** | 训练中的短时显存峰值可能导致显存不足 | 利用 NVIDIA 统一内存，按内存页管理优化器状态：显存紧张时迁到 CPU 内存，用到时迁回 GPU |

分页优化器主要提高低显存环境下的可运行性，不会提升速度，因为 CPU 和 GPU 之间传输数据有额外开销。

**代码流程（6.4.2）**

```text
BitsAndBytesConfig → from_pretrained(quantization_config=...)
→ prepare_model_for_kbit_training → get_peft_model → SFTTrainer
```

- **`prepare_model_for_kbit_training`：** 冻结基础模型，并把未量化的 FP16/BF16 参数转成 FP32，提高数值稳定性。
- **合并：** 不能直接在 4-bit 权重上合并，要先以 BF16 或 FP16 重新加载基础模型和 Adapter。

## Q6 微调的显存构成和静态显存估计

**显存构成（5.4.1）**

$$M_{train} \approx M_{weight} + M_{gradient} + M_{optimizer} + M_{activation} + M_{runtime}$$

| 类别 | 组成 | 能否预估 |
|---|---|---|
| 静态显存 | 模型权重、梯度、优化器状态 | 能，主要由参数量、训练精度和优化器决定 |
| 激活值 | 前向计算的中间结果 | 难，受单卡批次、序列长度、模型结构和梯度检查点影响 |
| 运行时开销 | 临时张量、通信缓冲区、CUDA 上下文、内存碎片 | 难 |

**静态显存估计（以 BF16 混合精度 + AdamW 为例）**

全参数微调每个参数占 18 字节：

| 组成 | 字节 |
|---|---|
| BF16 模型参数 | 2 |
| FP32 参数副本 | 4 |
| 梯度 | 4 |
| AdamW 优化器状态（一阶、二阶动量） | 8 |
| **合计** | **18** |

设基础模型参数量为 P，新增可训练参数量为 T：

| 方式 | 公式 | 说明 |
|---|---|---|
| 全参数 | $18P$ | 所有参数都有完整的训练状态 |
| LoRA | $2P + 18T$ | 基础模型只存权重 |
| QLoRA | $M_{4\text{-bit base}} + 18T$ | 基础模型的主要线性层以 4-bit 保存 |

**代入 Qwen3-0.6B（r=16，all-linear）**

P = 751,632,384，T = 10,092,544（由上面 Q4 的实测值相减得到）。

| 方式 | 计算 | 静态显存 |
|---|---|---|
| 全参数 | 18 × 751,632,384 | 约 12.60 GiB |
| LoRA | 2 × 751,632,384 + 18 × 10,092,544 | 约 1.57 GiB |

这只是公式算出的静态部分，不是完整的训练显存，也不是实测值。LoRA 不会按相同比例减少激活值，单卡批次或序列长度较大时仍可能显存不足。

**选卡流程（5.4.2）**

1. 根据微调方式计算单卡所需显存。
2. 选择容量满足要求并留有余量的显卡。
3. 用正式训练参数跑一个训练步，验证实际显存。
4. 结合测试结果、租用价格和可用性确定环境。

**对照 [06_lora_demo.py:62-89](../06_lora_demo.py#L62-L89) 算一遍**

- **每次更新的样本数：** 4 × 8 = 32。
- **总样本数：** 32 × 300 步 = 9,600，约等于 10,000 条数据的 0.96 轮。
- **预热步数：** `warmup_steps=0.1` 即 300 × 0.1 = 30 步。
- **评估和保存：** 每 50 步一次，共 6 次。
